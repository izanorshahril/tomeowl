# Jev and local decision models for Tomeowl

Checked: 2026-10-04.
Recent-evidence window: 2026-09-04 through 2026-10-04.
Method: verify vendor documentation, upstream repositories, model cards, releases and research papers; no packages or weights were installed and no private catalog was transmitted.
Repository `main` pages describe the checked state, not an immutable version suitable for installation.

## Recommendation

Keep Tomeowl's SQLite evidence store and native retrieval as the default.
Evaluate a local decision model as an optional controller after expanding the independent retrieval suite and improving packet selection.
The [current evaluation](../RETRIEVAL-EVALUATION.md) retains 11 of 14 annotated anchors: two remaining misses involve packet chunk selection and one involves vocabulary differences.
A decision scorer can select among existing candidates; it cannot recover an unseen document without an additional retrieval path.
Embedding retrieval addresses that vocabulary problem separately, while the controller could later rank candidate chunks, choose graph views or propose memory types.
These are architectural recommendations, not measured model improvements on Tomeowl.

## What the Jev hype refers to

TypeSafe launched Jev on 2026-09-15 as a hosted System One model: unstructured state plus predefined questions produce typed choices, ordinal scores and binary judgments rather than free-form answers.
Its vendor speed and calibration claims concern that constrained decision workload; schema correctness does not establish factual correctness of a selected answer.
The reviewed official product documentation does not provide downloadable Jev weights for a local deployment ([launch announcement](https://typesafe.ai/blog/introducing-system-one-models-and-jev), [official API](https://api.typesafe.ai/redoc)).

The 2026-09-29 Jev benchmarking preprint evaluates `jev-1.13.0` on 37 datasets and 346,009 requests.
Its authors report strengths on short classification tasks, but weaker low-resource language, legal and rubric judgments; binary thresholds need application-specific tuning.
It contains no relevance-judgment task and compares two open models through a single forward pass without their reasoning modes.
Consequently, it does not establish that Jev is the best RAG reranker or that an API-compatible local model matches it ([paper and limitations](https://arxiv.org/html/2609.37647v1)).

## Local candidates are distinct projects

| Candidate | Verified role and local limits | Tomeowl fit |
|---|---|---|
| [daseinlabs/open-jev](https://github.com/daseinlabs/open-jev) | Gemma 3 4B continuation-option scoring with shared-prefix cache; PyTorch scoring supports Windows/Linux CPU/GPU, while feature/head training remains MLX on Apple silicon. CPU uses float32; upstream warns GPU weights alone need about 8 GB at 16-bit. | A design/reference implementation rather than a lean default. Its README explicitly says zero-shot likelihood probabilities are uncalibrated. |
| [razorback16/openjev](https://github.com/razorback16/openjev) | Independent Jev-compatible server: DiffusionGemma 26B-A4B uses vLLM with NVIDIA GPU of at least 24 GB or MLX with about 16 GB free; smaller Laya/Verdict backends use PyTorch CPU/GPU. Its confidence is normalized entropy. | Useful API reference; large diffusion backend adds hardware and serving requirements. No Windows-native diffusion deployment was verified. |
| [Laya](https://github.com/NandhaKishorM/laya) | Decision encoders with CPU/PyTorch and ONNX paths; English ModernBERT-large 421M, multilingual mmBERT 322M. Maintainer documents a Windows construction fix and explicit calibration/abstention APIs. | Leading candidate for a bounded local controller experiment, conditional on domain labels and Windows packaging measurements. |
| [Verdict](https://github.com/Heman10x-NGU/Verdict-open-jev) | ModernBERT/GLiClass 151M; direct ONNX CPU inference; 512-token input and 24 substantive options plus an insufficient-evidence slot. | Smaller comparison candidate, preserving its abstention output and testing beyond its banking-oriented evaluation. |
| [lookski/openjev](https://github.com/lookski/openjev) | Another independent implementation, default Qwen3-0.6B, CPU and Windows support claimed; reports raw masked softmax probabilities. It can also use configured remote APIs. | Mechanism reference; its interface does not reproduce Jev's trained calibration or prove decision quality. |

Laya's maintainer reports base zero-shot typed-decisions performance near chance, while the workflow-specialized checkpoint performs better; both base checkpoints are overconfident and the multilingual model lacks fitted temperatures.
Long-document window aggregation does not turn a deciding-window probability into calibrated whole-document confidence ([Laya limitations and calibration](https://github.com/NandhaKishorM/laya)).
The [typed-decisions checkpoint](https://huggingface.co/convaiinnovations/laya-typed-decisions) is an English 1,024-token model specialized on four enterprise workflows, not a pretrained Tomeowl memory policy.
The checked [0.3.26 release](https://github.com/NandhaKishorM/laya/releases/tag/v0.3.26), dated October 3, adds a .NET ONNX SDK and TypeScript calibration support; these are deployment options, not validation of retrieval quality.

The razorback server removes Verdict's insufficient-evidence probability and renormalizes the other choices to fit Jev's wire format ([actual encoder implementation](https://github.com/razorback16/openjev/blob/main/openjev/encoders.py)).
For Tomeowl, a direct bounded scorer retaining abstention is preferable to that projection.
The checked razorback [package manifest](https://github.com/razorback16/openjev/blob/main/pyproject.toml) identifies version 0.5.0 but pins Laya 0.3.6, so new direct-Laya capabilities must not be assumed available through that wrapper.
Verdict's own report also shows calibration can worsen some held-out metrics, demonstrating why a calibration feature is not a universal quality guarantee ([evaluation table](https://github.com/Heman10x-NGU/Verdict-open-jev)).

## Jev-Mem is the closest architectural match

The September 21 [Jev-Mem preprint](https://arxiv.org/html/2609.23986v1) separates a decision controller, a memory data plane and an answer-synthesis model.
The controller handles typing, relation judgments, routing, candidate scoring and stopping; anchor retrieval already fuses vector and keyword rankings.
The authors report LoCoMo answer-judge score 0.777, construction 158 seconds and average query 0.93 seconds with the hosted Jev configuration.
These are one system's reported conversational benchmark measurements, not a comparison against Tomeowl or proof of general state of the art.

[Jev-Mem upstream](https://github.com/libingzheren/Jev-Mem) added local Laya integration on September 27 and explicitly states its paper has not benchmarked that backend.
Its current runner warns inherited reference-aware `best-of-n=3` selection can bias accuracy; use `1` for a single-answer experiment.
The LongMemEval runner uses a lenient scorer rather than the official metric, and its construction timing excludes initialization.

Local control alone does not make the entire Jev-Mem pipeline offline: its [Laya guide](https://github.com/libingzheren/Jev-Mem/blob/main/docs/laya.md) still uses a configured OpenAI-compatible answer/judge provider and downloads weights on first use.
That guide documents Windows/PyTorch configuration, bounded question batches, fingerprinted backend caches and long-state truncation risks.
Its Laya profiles permit much longer time budgets than the paper's fast hosted path; running forward passes are not preemptible.

## Exact licenses and adoption gate

[dasein code](https://github.com/daseinlabs/open-jev/blob/main/LICENSE), [lookski code](https://github.com/lookski/openjev/blob/main/LICENSE) and [Jev-Mem](https://github.com/libingzheren/Jev-Mem/blob/main/LICENSE) are MIT.
[razorback code](https://github.com/razorback16/openjev/blob/main/LICENSE), Laya code and the checked [Laya typed-decisions](https://huggingface.co/convaiinnovations/laya-typed-decisions) and [Verdict](https://huggingface.co/heman10x/rlcd-modernbert-151m) checkpoints declare Apache-2.0.
[Gemma 3 4B](https://huggingface.co/google/gemma-3-4b-it) has separate Gemma terms and gated access.
The [NVIDIA DiffusionGemma NVFP4 card](https://huggingface.co/nvidia/diffusiongemma-26B-A4B-it-NVFP4) declares Apache-2.0 but also links Gemma terms and prohibited-use policy under governing terms; review the precise pinned artifact rather than transferring a server's code license to its weights.

Before adding any optional local provider, pin code, model, tokenizer and preprocessing revisions; require cached/local weights and explicit offline execution, never an automatic cloud fallback.
Measure source/anchor recall, candidate selection, false memory admission, contradiction handling and insufficient-evidence detection on independent held-out examples.
Measure calibration with Brier/NLL and selective accuracy at coverage, plus p50/p95 latency, initialization time, peak memory and package size on the target Windows CPU.
Compare rules/native selection, compact Laya and Verdict before a multi-billion-parameter model.
Keep model judgments separate from accepted memory and citation truth: record provenance and allow proposals, while Tomeowl validates source IDs, revisions, quotes, limits and explicit admission.
No model was run during this research, and no local candidate has passed these adoption gates.
