## Upstream systems

| Project | What the upstream sources establish | Interfaces and constraints |
|---|---|---|
| [QMD](https://github.com/tobi/qmd) | Local document search combining SQLite FTS5/BM25, dense vector search, query expansion, RRF, and local GGUF reranking via `node-llama-cpp`. Its primary target is Markdown notes, docs, transcripts, and knowledge bases. The default model set is roughly 2 GB combined and downloads on first use. | CLI (`search`, `vsearch`, `query`, `get`, `multi-get`, `update`, `mcp`), stdio or localhost Streamable HTTP MCP, and a Node/Bun library API. JSON output and line-addressable document reads make it a practical retrieval adapter. Requires Node >=22 or Bun; no service is needed for CLI/stdio. Its vector index is tied to the selected embed model. HTTP endpoints have no authentication, so keep them loopback-only unless put behind a trusted boundary. Windows support has active fixes; QMD v2.5.2 specifically fixed Windows global launcher execution. Current upstream release page lists v2.8.3, dated 2026-08-16. Repository snapshot: about 1.9k stars and 692 commits. |
| [Graphify](https://github.com/Graphify-Labs/graphify) | The official distribution is Python package `graphifyy` (CLI command `graphify`), not a Go/C++ runtime. Local code extraction uses tree-sitter; semantic extraction for documents/media can use a configured model provider. It emits `graph.json`, `GRAPH_REPORT.md`, and an interactive `graph.html`; CLI supports query/path/explain, SVG/GraphML/wiki/Obsidian exports, update, and optional MCP. It has 37 tree-sitter grammars covering C/C++ and Verilog/SystemVerilog. PDF, common images, Markdown, Office files, and audio/video are supported by format-specific paths/extras, but this does not equal domain-aware schematic or tester-manual understanding. | Python >=3.10; Windows is documented. Install via `uv tool install graphifyy` (optional extras add capabilities). `graphify extract --code-only` is the deterministic, local, no-key route. Document/media semantic extraction may invoke an external or local LLM backend; the default product flow is broader than deterministic AST parsing. Outputs are reusable files rather than a general-purpose transactional graph database. v0.9.72 was released 2026-09-29. The README advertises separate LOCOMO/LongMemEval memory QA results and zero LLM credits for graph build; those are upstream-reported benchmark claims, not evidence for the video's 40% project-context savings. |
| [GBrain](https://github.com/garrytan/gbrain) | Bun/TypeScript memory and knowledge-base application. Current upstream offers a keyless local PGLite mode, Markdown import, CLI search/think, and MCP serving. The optional `--surface verbs` presents seven verbs: `recall`, `remember`, `entity`, `synthesize`, `forget`, `context_pack`, and `delta`. Search may combine keyword/vector retrieval and reranking depending on configured services; don't assume semantic embeddings are local or keyless. | CLI and MCP stdio/HTTP; PGLite by default, with Postgres/pgvector deployment options. The Git repository is the Markdown system of record, synchronized into a retrieval database. It can be adopted as a complete brain but introduces its own runtime, schema, DB/index lifecycle, and operational concepts alongside QMD. The upstream README snapshot reports ~30.1k stars and 1,071 commits; repository instructions say use Bun/GitHub installation, not the unrelated npm package named `gbrain`. No GitHub Releases page was found in the inspected sources; version/upgrades are tracked through repository channels. |

## Corrections to `RESEARCH.md`

- QMD is not “C++ / Go / GGUF.” The application and CLI are TypeScript/JavaScript for Node/Bun; GGUF is used by its embedded inference runtime, and SQLite provides the local index.
- Graphify is not only deterministic AST parsing. Code-only tree-sitter extraction is local and deterministic; broader document/media ingestion has optional semantic LLM extraction. Its graph may include explicitly tagged inferred edges.
- The video’s reported 40% saving is not an independently established result. The third-party summary does not expose a benchmark corpus, repeated runs, token accounting, or a comparable baseline. Graphify's own benchmark feature and upstream memory QA benchmark are different claims and should not be substituted for this measurement.
- The `RESEARCH.md` target architecture (Rust, SQLite FTS5 + vectors, Graph/relational/blob stores, MCP/TUI/CLI, pre-compaction hooks, automatic consolidation) is a proposal. The surveyed repositories do not demonstrate that this combined architecture is already needed or that its features will outperform a smaller QMD-centered tool.
- The local QMD configuration checked in the workspace shows an existing project-local index with two Markdown collections and explicit embed/generate/rerank model configuration. The index database exists. A bounded `D:\Dev` search did not find a Graphify output/config directory, so do not infer that Graphify is currently installed or indexed from `RESEARCH.md` alone. No document contents or project identifiers beyond the locally authorized research scope are reproduced here.

## Fit for a minimal Tomeowl prototype

Keep QMD as the first retrieval engine and integration contract: collection scoping, hybrid retrieval, local inference, MCP, JSON, and precise `get` ranges already cover the immediate “find relevant evidence without dumping a repository” problem. Reuse its CLI/MCP/API rather than embedding its storage schema. Keep Graphify as an optional graph extraction/export adapter for code and document relationships, with graph output linked back to original paths and extraction confidence. Avoid introducing GBrain as a runtime dependency unless the product needs its durable memory semantics (write/forget, entity model, synthesis, multi-agent scoping) after the first use case has been validated.

For the semiconductor workflow, these tools are ingredients, not a complete ingestion or engineering model. QMD's Markdown-first indexing needs parsers to yield text/metadata and stable source locations. Graphify supports common source code and documents, but its documented extension list does not establish direct parsers for proprietary ATE programs, STDF datalogs, EDA schematic formats, or tester-specific pin/netlist semantics. The first vertical slice should compare source PDFs, extracted tables, test program symbols/limits, board netlists, and a small known-good query set; require answers to cite source file plus page/line/table and preserve uncertainty. Treat numeric limits/datalog values as structured records with units/revisions rather than trusting semantic similarity alone.

Before adopting a claimed context-saving percentage, measure the same tasks against a fixed corpus: baseline full-context input tokens, indexed retrieval input tokens, answer/citation correctness, recall of exact part/test/pin identifiers, wall time, and model/index disk usage. Keep exact-identifier queries in the evaluation set because semantic retrieval can miss near-identical pin names and limits.
